# Examples

`run-records/` holds sample run records (the JSON written by `review-harness run --record-dir`).
They are **synthetic**: generated by `cargo run -p harness-core --example gen_records` from scripted
scenarios using `MockProvider`. No real LLM was called and no real pull request is described.

| File | Scenario |
|---|---|
| `pr-101-round-1.json` | docs-only change, no provider configured: AI layer "skipped: no provider configured" |
| `pr-102-round-1.json` | failing test: gate FAIL, AI skipped so no tokens are spent |
| `pr-103-round-1.json` | AI reports 3 findings, 2 point outside the diff and are dropped as hallucinations |
| `pr-103-round-2.json` | second round after the fix, clean |
| `pr-104-round-1.json` | workflow change (high risk) and the provider times out: AI layer fails closed |

Try the metrics command on them:

```
review-harness metrics --records examples/run-records
```

Scanners are disabled in these scenarios, so every record is "needs human" or "fail": a skipped
scanner never counts as a pass.
